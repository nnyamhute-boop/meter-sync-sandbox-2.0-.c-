- **Installer hardening v2** ([products/promun/grpc/installer/](products/promun/grpc/installer/), [products/unipay/sync/installer/](products/unipay/sync/installer/)): five inter-locking fixes that take the MSIs from "installs but rarely runs cleanly" to "installs, starts, survives reboots, and tears down without leaks". (1) **Smart port resolution** — a new `Resolve-ServicePort.ps1` scans `[BasePort, BasePort+RangeSize)` for the first port that's neither in the OS's excluded range (Hyper-V/HTTP.sys-reserved, surfaced by `netsh int ipv4 show excludedportrange`) nor held by a real TCP listener, with `-PairOffset` semantics for HTTP+HTTPS pairs. `Configure-PromunEndpoints.ps1` and `Configure-UnipayEndpoints.ps1` wrap it as MSI deferred custom actions; `Patch-Appsettings.ps1` regex-rewrites `Kestrel:Endpoints:*:Url` in the live `appsettings.json` to the resolved port. PS 5.1 compatible (Windows-PowerShell-only inside MSI custom actions). The chosen port is persisted under `%ProgramData%` so shortcuts and the firewall component agree at click time. (2) **WS2016+ launch condition** — both MSIs now reject Windows Server 2012/2012 R2 via a RegistrySearch on `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\CurrentMajorVersionNumber` (the registry value only present on Win10+/Server 2016+). Previous `VersionNT >= 603` lacked the granularity to discriminate; .NET 10 self-contained doesn't run on WS2012, so the launch condition fails the install with a clear message rather than letting the service silently fail to start post-install. (3) **Admin UI lockdown** — Promun's Blazor admin and Unipay's Hangfire dashboard are now restricted to loopback by default. Promun gained explicit middleware between `UseAntiforgery` and `MapGrpcService` that returns 403 on `/admin/*` from non-loopback `RemoteIpAddress`; opt-out via `Security:AdminUiAllowRemote=true`. Unipay's Hangfire `Authorization = []` (which DISABLED the default loopback filter — silent footgun) was replaced with a conditional `LocalRequestsOnlyAuthorizationFilter` with `Security:HangfireDashboardAllowRemote` opt-out. (4) **Firewall components** — `WixToolset.Firewall.wixext` added (`PackageVersion` in `Directory.Packages.props`); `FirewallComponents` ComponentGroup on each installer declares `<fw:FirewallException>` rules for the resolved port range (Promun 5001-5010, Unipay 5080-5089) instead of the previous single-port rule that broke whenever smart-port resolution picked a non-default.
